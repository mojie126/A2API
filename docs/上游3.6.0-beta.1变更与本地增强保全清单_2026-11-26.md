# 上游 3.6.0-beta.1 变更调查与本地增强保全清单（2026-11-26）

本文调查上游 beta 分支最新增量，并把本仓库（Agent2API / A2API）与插件仓库（Agent2Providers）的本地增强逐项对照，给出同步时的保留、采用与合并判定。逐日详细记录见 `docs/baseline-and-local-changes_2026-11-10.md`，当前状态索引见 `docs/上游同步与本地改动总览_2026-11-25.md`；本文只记录本轮增量与冲突结论。

对比方法：一律用工作树内容差异（`git diff 33f5e797..upstream/beta`）判断，不按提交数量；本地一侧对照 `33f5e797..feature/upstream-3.5.0-followup`，只记录与同步相关的结论。

## 一、范围与结论

| 项 | 内容 |
| --- | --- |
| 上游分支 | `upstream/main` 仍停在 3.5.1（`33f5e797`），只有 `upstream/beta` 前进 |
| 主仓库增量 | 5 个提交、443 个文件、+44188 / −7205 行，版本 `3.6.0-beta.1` |
| 插件仓库增量 | `upstream/beta` 比 `main` 多 9 个提交、64 个文件、+3323 / −908 行，8 家提供商升到 `0.1.1-beta.1` / `0.1.2-beta.1`，协议仍为 1 |
| 结论 | 新增定时任务插件、隐私脱敏、本机直连采集三个子系统，并重构插件页；本地增强在转发链路、请求统计、插件宿主与界面大面积重叠，必须逐文件手工合并 |

## 二、上游 3.6.0-beta.1 变更明细

### 2.1 定时任务插件体系

- 数据层：`db/schema_task_plugins.sql` 新增 `task_plugins`（插件声明与脚本）、`task_jobs`（任务实例与加密参数）、`task_job_runs`（执行记录），迁移占用 schema v33
- 接口：`/api/task-plugins`（列表、创建、导入、商店安装、解析、预览、导出、启停与权限）、`/api/task-jobs`（列表、创建、修改、删除、复制、立即运行、停止、自定义动作、运行记录、Cron 校验与预览）
- 执行器：单文件 `.js` 插件以 `@agent2api-task-plugin` 声明表单、按钮、状态卡片、域名白名单与通知权限，正文实现 `onAction` / `onSchedule`；QuickJS-NG 沙箱内存 32 MiB、栈 512 KiB、硬超时与立即停止，无文件系统、子进程与环境变量
- 持久化：表单敏感字段与 `ctx.storage` 按任务用 AES-256-GCM 加密；导出分享只含声明与代码，不含填写内容；商店安装带 Ed25519 签名、SHA-256 与大小校验
- 界面：新增「定时任务」页面、可视化编辑器（模板、实时预览、试跑、与脚本代码双向同步）、插件页「其他插件 → 定时任务」入口，桌面端、网页端与手机端均有页面
- 依赖：`croner`、`chrono-tz`、`rquickjs`、`qrcode`
- 文档：`docs/task-plugins.md`

### 2.2 请求隐私脱敏

- 新增独立于「关键词替换」的出站处理层，位于角色归一、关键词替换之后，会话图片压缩之前；原生协议链路在 `native_payload` 同步接入
- 识别范围：密钥类（私有密钥、常见 API Key、JWT、钱包私钥、连接串密码、鉴权头、键值密钥、中文口令）与个人信息类（邮箱、手机号、身份证、银行卡默认开启，公网 IP、主目录用户名默认关闭），另支持自定义词表与前缀 / 正则规则
- 动作：`mask` / `warn` / `block`；`block` 直接返回 `privacy_blocked`，不重试其他账号，也不进入识图补救
- 还原：占位符映射只驻留进程内存（HMAC 派生、容量上限），响应流按块还原、JSON 整体还原；不写数据库与日志
- 配置：`privacyRedaction`，默认关闭；设置页新增「隐私脱敏」页，接口为 `/api/privacy` 与 `/api/privacy/test`
- 记录：`requests` 新增 `privacy_hits` 列（schema v34），请求日志新增隐私面板，显示类别、动作、次数与已还原次数

### 2.3 本机直连采集

- 读取未经网关的本地客户端历史：首期支持 Antigravity 桌面版、Insiders、agy 命令行、T3 Code 与 WSL 的 SQLite 会话库
- 写入请求日志与报表时按来源键去重，避免与网关记录重复；新增 `requests.origin`（`gateway` / `local_direct`，schema v35）与 `local_direct_refs`、`local_direct_files` 两张表
- 对话原文不落库，详情预览按索引路径实时读取；轮询默认 30 秒（可调 10 秒至 1 小时）
- 默认开启 Antigravity 采集；配置键 `localDirectAgents`，接口 `/api/agents/local-direct` 与 `/api/agents/local-direct/sync`

### 2.4 插件页重构与其他

- 插件页改为左侧分类栏与行式列表，新增「其他插件 → 定时任务」，批量本地安装未签名插件改为点击时二次确认；脚本插件列表拆出控制器与流式尾部
- 新增 New API 类通道的钱包余额与订阅额度解析（`/api/user/self`、`/api/status`、`/api/subscription/self`，含扣费偏好与两位小数）
- 桌面托盘与原生系统弹窗补齐六语言同步切换；统计报表支持合并查看；请求详情与签到福利面板改版
- 插件安装接口支持定时任务 ZIP 的预览与安装；插件列表接口新增 `rev` 参数，内容未变化时只返回摘要，减少轮询体积
- 脚本插件新增跨机身份映射（`scriptPluginIdentities`），处理不同机器上同一包拿到不同提供商 ID 的冲突，随云同步与整库备份迁移，云同步恢复后自动对齐
- 构建：新增根目录 `.cargo/config.toml` 统一 `target`；CI 删除 `warm-cache.yml`，测试矩阵固定 `macos-26`，增加服务端可执行入口编译检查；发版助手支持远端尚不存在的新分支

### 2.5 数据结构与接口变化汇总

| 项 | 变化 |
| --- | --- |
| schema | v33 任务插件、v34 隐私命中列、v35 来源通道列与索引 |

### 2.6 两个后续修复

- 商店定时任务插件下载误用图标接口导致地址校验失败：新增 `plugin_download_url` 只放行官网与 CDN 的插件路径，加强制下载校验、流式大小与完整性校验
- 配额弹窗满额（≥100%）时不再显示「未返回重置时间」，桌面与网页端同步

## 四、冲突点与合并要点

1. **数据库版本号冲突（最高优先）**：本地 `SCHEMA_VERSION = 34`（v33 用量诊断、v34 签到索引），上游 beta 也使用 33/34/35。同步时把上游三段顺延为 35/36/37，最终版本 37；本地新增 SQL 文件保持不变，`RESERVED_KV_KEYS` 取并集。
2. **转发链路签名变化**：上游把 `send_body` 与 `native_payload::prepare` 改为返回 `Result` 以支持隐私拦截，改动 `provider_loop` 多处；本地该文件有约 350 行自有逻辑（WARP、路由组、错误策略），必须按调用点逐段加回。
3. **请求统计**：上游在本地已有的轻量列表、详情接口与 SQL 上叠加隐私、来源与费用重算字段；以本地结构为基线，逐字段补入，禁止整文件替换。
4. **插件宿主**：上游新增脚本插件身份映射、任务插件商店、取消令牌与 WASM 运行时构造；本地原生插件放行、安装目标回退与 fork 更新源必须逐条加回。上游删除 `checkin_call/doubao_daily/claim.rs`，与本地签到改动冲突，按本地上游跟进结论处理。
5. **界面**：请求页、插件页、设置页、路由页与手机端在两侧都大改，按页面为单位以上游为基线、逐项加回本地交互；i18n 源文件合并后统一重建词典。
6. **工作流**：上游删除 `warm-cache.yml`、调整 `build.yml` 与 `rust-tests.yml`；本地只保留「测试矩阵固定 `macos-26`」与「服务端入口编译检查」，其余自建流程不动。
7. **插件仓库**：上游只改 `wasm/<提供商>`，本地实现在 `crates/providers/src/providers/<提供商>`，按提供商手工移植，禁止直接取文件；协议未升级，无需改协议库依赖。

## 五、建议的同步顺序

1. 先处理本地回归与小修（本轮悬停面板已修）。
2. 引入三个新模块与迁移：`core/task_plugins`、`core/privacy`、`core/local_direct`、对应接口与 SQL 文件，先完成 schema 顺延与保留键合并。
3. 合并转发链路：`send_body` / `native_payload` 的 `Result` 签名、隐私层、响应还原与 `provider_loop` 调用点。
4. 合并请求统计与界面：以本地轻量列表、事件刷新与弹窗判据为基线，叠加隐私与来源展示。
5. 合并插件宿主：原生放行、安装目标回退、fork 更新源、身份映射与取消令牌。
6. 插件仓库按提供商移植，再统一升级包版本与发布说明。
7. 回归：服务端 `cargo test --release -p agent2api-server`、页面岛类型检查与构建、词典重建、手机端构建；验证 WARP 出口、路由组并发、识图原图直转、客户端归属、原生插件安装、请求日志与云同步恢复。

## 六、本轮已完成的修复

- 现象：请求日志悬停「敏」标签显示「这条记录命中了敏感词，但没有留下命中明细」
- 根因：列表已改为 `view=list` 轻量行，只带命中标记；`request-hover.tsx` 仍是旧版，缺少上游 3.5.1 引入的详情懒加载，面板读取空命中表后落入兜底文案
- 处置：按上游方案补入 `detailsLoaded` / `loadingDetail`、详情缓存与单条详情回填，重试链与敏感词面板在补齐期间显示「正在加载详情…」；保留本地尝试行展示 `userAgent` 的差异
- 验证：页面岛 `tsc --noEmit` 通过，`vite build` 产物包含详情回填逻辑，五个语种补充「正在加载详情…」词条并重建词典
