  - 自动维护执行记录新增「清理」按钮——执行记录工具条右侧一键清空全部已结束的记录（运行中的不动，孤儿明细一并回收），桌面与手机端各走自己的确认弹窗，清理后提示条数并刷新；后端新增 `POST /api/maintenance/records/clear`
  - 自动维护设置弹窗的保留策略保存修复——提交的键名（`retentionDays` / `maxRecords`）与 `/api/retention` 的校验键（`maintenanceRecordRetentionDays` / `maintenanceRecordMaxCount`）不一致，后端把未知键静默忽略后原样返回当前值，表现为「保存无效」且不会立即清理；修正为与后端一致的键名，保存即落库并触发立即清理
  - 客户端识别面板头部的「添加规则」移入「自定义头匹配规则」区块脚部——头部入口悬在面板顶上、位置与区块脱节；按钮与数量上限判断原样保留，脚部补识别顺序说明，请求详情的规则弹窗已按识别管线重做

## 部署与运行基线（2026-11-08 实测）

### NAS Docker 部署

- 宿主机：ZD-NAS（群晖，x86_64，Intel Atom D2701，物理内存 988 MB，启用 swap）
- 容器：`a2api`（镜像 `ghcr.io/mojie126/a2api:latest`，Portainer 创建），端口 3065:3065，数据卷 `/volume1/docker/portainer/agent2api/data:/data`
- 环境变量基线：`AGENT2API_IMAGE_CACHE_MB=32`、`AGENT2API_IMAGE_COMPRESS_CACHE_MB=32`（默认各 128，最坏合计 256 MiB，1 GB 机器收窄到 64 MiB）、`MALLOC_CONF=background_thread:true,dirty_decay_ms:5000,muzzy_decay_ms:5000`（jemalloc 主动归还内存，抑制长稳 RSS 缓涨）
- 重启策略：`no`（原样保留；面板内一键更新依赖重启策略拉起容器，当前配置下更新后不会自动恢复，需手动启动）
- 实测内存：调整后重启约 36 MiB（调整前运行中约 86 MiB）

### Bun 运行时兼容性

- 网关把 Bun 版本钉在 `1.4.2` 并带 SHA-256 校验（`server/src/server/core/plugin_host/script/bun.rs`），按平台自动选择官方构建
- NAS 实测矩阵：v1.4.2 与 v1.4.4 的 `bun-linux-x64-baseline` 在 D2701 上均为 SIGILL（退出码 132，该 CPU 缺 SSE4.1/4.2、POPCNT、CMPXCHG16B、AVX）；v1.1.0 的 baseline 可正常运行（退出码 0）
- 结论：脚本插件（Magpie / OpenCode v1）在该 NAS 上不可用，旧版 Bun 虽能启动但版本钉死且插件宿主按现行 Bun API 编写，不构成可行支持路径
- 清理入口用于启动失败后的重置：删除运行时目录，下次使用脚本插件时按需重新下载

### 本地桌面构建（2026-11-08）

- 构建脚本：`scripts/build-desktop.ps1`，串联 i18n 词典 → 页面岛 → 手机端 bundle → Rust 四步，三个前端步骤按源码与产物修改时间增量跳过；`ui/` 在编译期被 `generate_context!` 嵌进桌面壳二进制，脚本把上次嵌入时的内容指纹（相对路径加文件内容哈希）持久化到 `target/ui-stamp.txt`，指纹变化即删除桌面壳的产物与 fingerprint 强制重编重嵌，server 库与其余依赖继续走缓存（不用 `cargo clean -p`，它按当次选择的单元清理，会漏掉整包构建留下的产物）；词典这类「重写但内容不变」的产物不会改变指纹，不触发无谓重链
- 构建前自动停掉「从 target 目录启动」的运行中实例（只认 target 目录下的进程，不碰其它安装），避免运行中的程序锁住产物文件导致链接失败
- 缓存位置全部在仓库内：Rust 共享 `target/`（`src-tauri/.cargo/config.toml` 钉死），Node 依赖用各包自带 `node_modules/`；脚本不写用户全局目录，Windows 工具链自动前置 `D:\msys64\mingw64\bin`
- 已知环境限制：`workbuddy-proxy-desktop` 的测试二进制在 windows-gnu 下加载阶段报 `STATUS_ENTRYPOINT_NOT_FOUND`（PATH 里 mingw 运行时 DLL 冲突；该 crate 没有任何测试，与代码无关），`-Test` 因此只跑 server crate 的测试
- 产物：`target\release\agent2api.exe`（桌面壳，二进制名已与 Tauri CLI 打包名一致）与 `target\release\agent2api-server.exe`（headless 网关）
- 常用参数：`-DebugBuild` 调试档、`-Test` 构建后跑 server crate 测试、`-FrontendOnly` 仅前端、`-SkipFrontend` 仅 Rust、`-ScanI18n` 先扫描词典新键、`-Force` 全部重建、`-Bundle` 追加 NSIS 安装包（需 `cargo install tauri-cli --locked`，本地未装）、`-Proxy http://127.0.0.1:7890` 首次拉依赖走本地代理
- 构建只保留 release（2026-11-10 起）：debug 谱系已清理（A2API `target\debug` 38.46 GB + 插件仓库 `target\debug` 3.83 GB，共回收 42.29 GB），本地无断点调试需求；后续 `cargo test` 与 `cargo check` 一律加 `--release`（复用 release 依赖缓存，不产生 debug 谱系），确需断点调试时再临时构建
- 行尾幻影修改根治——生成器（词典编译 build.mjs、vite）固定输出 LF，仓库 `core.autocrlf=true` 检出为 CRLF，每次重建产物在两种行尾间翻转，git status 出现大量 diff 为空的幻影修改（本轮 95 个 i18n 产物条目）；两道修复：`.gitattributes` 锁定 `desktop-tauri/ui/** text=auto eol=lf`（与 `.githooks/**` 同一先例），词典编译器 build.mjs 对内容一致（行尾归一后）的产物跳过写入；`ui/sw.js` 的缓存指纹随 bundle 内容哈希变化属设计行为，不算噪音
- 注意：AI 会话的执行沙箱对 `.git` 只读，git add / renormalize 无法持久化索引，幻影条目需要在正常环境跑一次 `git status` 或随下次提交自然消除
