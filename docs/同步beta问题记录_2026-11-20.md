# 同步官方 beta.2/beta.3 问题记录（2026-11-20）

本轮用 `git merge upstream/beta` 把官方 beta.2（`0affd3af`）与 beta.3（`cd0411bf` 及其后提交）合入 `develop`，随后出现一串「功能还在文件里、但关键一行被上游版本替换」的静默回归。本文逐条记录现象、根因、修复与提交，供下次同步核对。

> 结论先行：**同步上游一律手动逐行合并，禁止 `git merge` / `git cherry-pick`**。自动合并不会报冲突，只在行为上回归。

## 一、闪退（栈溢出）

- 现象：桌面端 `agent2api.exe` 与 headless 都在启动后十几秒 `thread 'tokio-rt-worker' has overflowed its stack`，进程直接退出
- 根因：beta.2 起插件调用链（`rpc.rs` 的 `call`）叠加了账号出口、余额队列、容量准入、查询诊断等多层作用域包装，async 状态机在默认 2 MiB 工作线程栈上生成即溢出。beta.1 没有这些包装，所以正常
- 修复：headless（`bin/agent2api-server.rs`）与桌面壳（`src-tauri/src/lib.rs`，Tauri 运行时用 `async_runtime::set` 换成 8 MiB 栈的运行时）都显式设置 8 MiB 工作线程栈
- 提交：`a27d9d85`（headless）、`f5b60f75`（桌面）

## 二、原生插件包无法安装

- 现象：安装 `agent2api-providers-3.5.0-beta.x-x86_64-pc-windows-msvc.zip` 报「插件包没有为当前平台（x86_64-pc-windows-msvc）提供入口」，界面「无法安装」
- 根因：上游把 `install::entry_for_target` 改成只认 WASM 目标、忽略传入平台，原生包（entry 按本机三元组）永远取不到入口；同一条约束还残留在安装、启用、子进程启动三处
- 修复：入口先按传入平台取、取不到才回退 WASM；放开 `packages.rs` 的 `if !is_wasm`、`operations.rs` 的资产目标校验、`lifecycle.rs` 的非 script 拦截；新增回归测试钉住入口选择顺序
- 相关决策：本 fork 保留原生插件体系（`support.rs` 恒 Supported、`legacy_reason` 恒 None），同时兼容 WASM 包
- 提交：`4c659abc`

## 三、特殊请求路由点路由组不跳转（回归）

- 现象：停留在压缩上下文 / 辅助识图 / 标题生成面板时，点左栏路由组或模型不切换
- 根因：渲染链以 `specialKey` 优先于路由组与模型路由，切换时须清空它；合并时 `onGroup`/`onModel` 回调里的 `setSpecialKey(null)` 被上游版本覆盖（该问题 11-16 修过一次）
- 修复：两个回调补回 `setSpecialKey(null)`
- 提交：`5591fa62`

## 四、配置保存后快照不重建

- 现象：标题生成、压缩上下文、客户端识别、图片兼容、路由配置保存成功后界面回退，再次保存撞修订号冲突
- 根因：上游 `update_inner` 只重建 `model_rules`，不再调本地 `refresh_derived` 重建其余派生快照
- 修复：`update_inner` 对六类配置键逐项比较并重建派生快照
- 提交：`ea765153`

## 五、动态登录指引链接不可点击

- 现象：插件登录指引里的 https 链接变成纯文本
- 根因：上游改用新的登录组件，指引按 `{instructions}` 纯文本渲染，本地 11-14 的「链接转系统浏览器」丢失
- 修复：用 `instructionParts` 拆分并在链接上调用 `openExternal`
- 提交：`ea765153`

## 六、WebDAV 恢复覆盖本地账号设置

- 现象：从云端恢复后，本机改过的余额查询间隔、代理、User-Agent、并发上限等被旧快照覆盖
- 根因：恢复是全量替换（先清表再插入远端行），没有本地优先的概念
- 修复：同 id 账号按字段合并，本地偏好字段（`usageQuery`/`proxy`/`userAgent`/`maxConcurrent`/`name`）与列（`enabled`/`priority`）优先，凭证等其余字段取远端；本地没有的账号照常新增；远端数据解不开时原样写入不丢行
- 提交：`17b63474`

## 七、组内并发被容量准入绕开

- 现象：路由组「组内并发设置」不生效
- 根因：上游新的 `account_admission::select` 与 `all_busy` 只读账号自身 `maxConcurrent`，没读路由组的 `routingConcurrencyCap`
- 修复：两处改读 `routing::concurrency_limit_of`
- 提交：`5dc8f042`（同步提交内）

## 八、工作流协议库校验

- 现象：升级网关版本号后 `fork-build` 的「协议库 tag 与网关版本一致」校验必然失败（协议库最高只到 `v3.5.0-beta.2`）
- 修复：校验改为「协议库 tag 在远端存在」
- 提交：`83d576e0`

## 九、无需续期的账号手动刷新报错

- 现象：DeepAI Code 手动刷新凭证报「当前未接入 Token 续期」
- 根因：静态 API Key 不会过期，但手动刷新统一按「该家不支持续期」报错
- 修复：不临期的账号按「无需续期」成功返回；确实会过期却无续期手段的家仍如实报错
- 提交：`9e45bcb1`

## 十、科搭续期提前请求被拒

- 现象：凭证续期失败「科搭上游返回 400：Token is not close to expiration」
- 根因：本地 48 小时续期窗口比上游允许的窗口宽，令牌仍有效时就请求续期
- 修复：该响应按「令牌仍有效、无需续期」处理并推进 `refreshedAt`，之后 30 分钟内不再重复请求
- 提交：插件仓库 `73ed158`

## 十一、WorkBuddy 长对话 400

- 现象：消息条数超过 512 的对话返回无提示的 400
- 根因：beta.2 新增的 WASM 固定投递路线把消息条数卡在 512
- 修复：新增 `MAX_MESSAGES = 2048`（落在请求体与节点数护栏之内）；上游若自行放宽应撤回
- 提交：`08ecd10b`
