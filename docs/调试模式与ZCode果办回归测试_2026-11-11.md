## 目的与边界

本轮不开启调试模式，本文记录下一次需要实际开启时的完整回归口径，覆盖调试采集档位、正文截断、上游与下游正文复用、有界异步写入、运行读数，以及 ZCode 自动领取验证和果办客户端状态模拟。

## 调试模式回归

### 档位与接口读数

通过管理面板登录，取得 `x-panel-token` 后先读取当前状态，不直接打开开关：

```powershell
$credential = @(Get-Content 'E:\develop\NAS.txt')
$username = $credential[0].Trim()
$password = $credential[1].Trim()
$session = New-Object Microsoft.PowerShell.Commands.WebRequestSession
$login = Invoke-RestMethod -Method Post -Uri 'http://192.168.1.11:3065/api/panel/login' `
  -ContentType 'application/json' `
  -Body (@{ username = $username; password = $password } |
    ConvertTo-Json) `
  -WebSession $session
$headers = @{ 'x-panel-token' = $login.data.accessToken }
Invoke-RestMethod -Uri 'http://192.168.1.11:3065/api/debug' `
  -Headers $headers -WebSession $session | ConvertTo-Json -Depth 12
```

现场凭据文件是两行纯文本，第一行是账号、第二行是口令；不要把账号、口令或令牌写入本文件、命令记录或提交信息。

以下字段必须同时存在：

| 字段 | 预期 |
|---|---|
| `debugMode` | 当前开关值 |
| `debugBudget` | `compact`、`standard` 或 `full` |
| `stats.captureBytes` | 当前档位采集上限 |
| `stats.storeBodyBytes` | 当前档位单条落库上限 |
| `stats.totalBytes` | 当前档位总正文上限 |
| `stats.queued` | 当前排队条数 |
| `stats.written` | 已批量写入条数 |
| `stats.truncated` | 截断次数 |
| `stats.dropped` | 因预算或库不可用丢弃条数 |

档位切换只改变预算，不应打开调试：

```powershell
Invoke-RestMethod -Method Put -Uri 'http://192.168.1.11:3065/api/debug' `
  -Headers $headers `
  -ContentType 'application/json' `
  -Body '{"debugBudget":"compact"}' `
  -WebSession $session | ConvertTo-Json -Depth 12
```

预期结果：`debugMode` 保持原值，`debugBudget` 变为 `compact`。分别切换 `standard` 与 `full`，确认数值随之变化；最后按测试环境恢复原档位。

### 正文截断与批量写入

实际开启调试后，在请求日志详情中验证以下内容：

1. 普通短请求保存完整的最终上游请求体和响应体。
2. 超过当前档位采集上限的响应保留头尾，正文中出现 `[debug body truncated: original=... bytes]` 标记。
3. 单条报文超过落库上限时仍保存地址、状态码、请求头和响应头，正文只截断，不整条消失。
4. 下游响应和上游原始响应字节完全相同时，`request_raw` 不新增第二份相同响应；请求详情仍能从 `debug_traffic` 回退读取上游正文。
5. 连续发送至少 `20` 次流式请求后，`stats.queued` 能回落，`stats.written` 与批次增长，`stats.batches` 不长期为零。
6. 对超过队列预算的高并发请求，`stats.dropped` 可以增长，但客户端请求本身不能因此失败。
7. 关闭调试后不再新增报文，已有数据按保留策略清理。

每次采集完成后读取一次统计，至少记录以下数值：

```powershell
Invoke-RestMethod -Uri 'http://192.168.1.11:3065/api/debug' `
  -Headers $headers -WebSession $session | ConvertTo-Json -Depth 12
```

验收以“请求正常、写入可回落、没有同步阻塞转发”为准。`writeMicros` 是累计写库耗时，不拿它直接推导机器性能；需要比较档位时应在相同请求规模和相同 NAS 状态下复测。

### 4 MiB 的官方口径与本机阈值

官方 `upstream/main` 与 `upstream/beta` 都不存在单条正文大小上限，调试报文完整保存正文，依靠条数保留策略清理；官方 `debug_traffic` 保留 `500` 条，`request_raw` 保留 `1000` 条。因此不能把 `4 MiB` 说成官方统一下发的限制。

本 fork 针对群晖 Docker 增加了按档位收紧的本地阈值。响应流首次超过采集上限时保留已收到的头部 `3/4`，此后滚动保留尾部 `1/4`，并写入带原始字节数的截断标记：

| 档位 | 单响应采集上限 | 单条落库上限 | 正文合计硬上限 | 有界队列 | 批大小 |
|---|---:|---:|---:|---:|---:|
| 精简，默认 | 1 MiB | 2 MiB | 32 MiB | 32 | 8 |
| 标准 | 2 MiB | 8 MiB | 64 MiB | 64 | 16 |
| 完整 | 4 MiB | 16 MiB | 128 MiB | 128 | 24 |

所有档位的记录条数仍受 `debug_traffic` 保留上限约束，正文合计另有硬上限。请求体超限时同样保留头尾。下游与上游正文一致时，两侧分别计算长度和 SHA-256 指纹，不复制、也不再次扫描完整上游正文；详情读取回退到 `debug_traffic`。下游正文同样按当前采集档位做有界头尾保持。调试写入由独立线程和大事务批量完成，队列满时丢弃调试数据，不能阻塞或失败正常转发。

官方与本 fork 的配置键不同：官方没有 `debugBudget` 档位；本 fork 新增 `debugBudget`，缺省或写坏时回落 `compact`。以后核对是否有新变化时，应以对应上游提交和当前部署版本为准，不能只引用本文结论。

## ZCode 回归

### WebUI 验证界面

页面必须保持打开，允许切到后台，但浏览器完全关闭后不能继续自动验证。打开签到中心后检查验证状态卡：

| 页面状态 | 预期 |
|---|---|
| 页面前台 | 显示运行中，持续心跳 |
| 页面后台 | 显示后台运行，仍可轮询 |
| 页面关闭 | 显示已关闭，不继续领取 |
| 实际出现滑块 | 必须人工完成，不应伪造验证成功 |

验证步骤：

1. 打开签到中心，确认页面状态提示存在。
2. 切到另一标签页，至少保持 `30` 秒，确认不再因 `visibilityState` 被误判为不可用。
3. 回到签到中心，确认心跳恢复且没有重复验证提示。
4. 关闭页面后等待一个验证任务期限，确认不会留下永久“等待验证”状态，签到记录明确记录需要重新打开界面。

浏览器层冻结 Worker 的情况不能让服务端假装成功。验收标准是“状态如实”和“恢复后能接任务”，不是无条件后台领取成功。

### 已领取事实与预览

对已领取账号执行只读预览：

```powershell
$accountId = 'zcode-intl-user-9a549894-466b-45aa-8fea-34aa737d6032'
Invoke-RestMethod -Method Post `
  -Uri "http://192.168.1.11:3065/api/accounts/$accountId/zcode-claim/preview" `
  -Headers $headers -ContentType 'application/json' -Body '{}' `
  -WebSession $session | ConvertTo-Json -Depth 20
```

验收条件：

- `plans` 中出现账号名下套餐，而不是仅因为目录为空返回空列表。
- `claimState` 为 `claimed`，`claimedAt` 与账号 `claimPlans` 一致。
- `dailyCheckin.completed` 为真，`sourcesComplete` 为真。
- `catalogError` 等来源错误单独显示，不把已领取事实改写为“未领到”。
- 已领取但权益尚未生效的套餐显示 `ownedPlan.state=pending`，页面提供待生效时间。

对没有当日套餐的账号，验收结果为 `plans` 为空或没有可领目标，签到记录为 `pending`，不能显示为红色失败。

另一个国际版账号 `130****8713` 的回归重点是：活动目录暂时为空时，仍必须读取账号名下套餐并显示 `userPlanId=upl_2120473334103777280`。修复前只在候选清单非空时查询名下套餐，于是出现“余额可见、套餐预览为空”的分叉读数。

### 下单与安全边界

回归不点击“领取”，除非当天实际存在可领套餐且已经准备好人工验证。验证失败、额度耗尽、没有验证界面的业务结果必须以 HTTP 200 返回业务分类，而不是被包装成 `500`。

## 果办回归

### 只读客户端状态模拟

打开签到中心果办分组，点击“只读模拟客户端”。后端请求为：

```powershell
$accountId = 'officeace-a6c870e3f045'
Invoke-RestMethod -Uri "http://192.168.1.11:3065/api/accounts/$accountId/officeace-subscription/simulate-client" `
  -Headers $headers -WebSession $session | ConvertTo-Json -Depth 20
```

预期字段：

- `simulation: official-control-plane`
- `readOnly: true`
- `clientInstalled: false`
- `subscribeStatus`
- `subscription`
- `bonuses`
- `trial`
- `autoRenew`
- `limitations`

同时检查返回值中不得出现 `model_app_key`、`model_app_secret`、访问密钥、安全令牌、刷新令牌或任何原始资源字段。模拟接口只返回固定白名单：订阅状态、套餐名称、额度、奖励、有效期、续费状态和非敏感套餐标识。

该项只读，不提交服务协议、不购买套餐、不改自动续费。没有安装客户端时，它能复现官方控制面能看到的订阅、奖励、试用资源和续费状态；客户端本地数据库、TLS 指纹、CloudWAF 会话不能模拟，结果中的限制列表必须如实显示。

这些读数说明签到与奖励结算成功，余额为零是额度耗尽，不是签到失败。若出现 `UNSUBSCRIBED`、`EXPIRED` 或 `FROZEN`，应按套餐状态处理，不能误报为签到接口故障。

### 果办验收

1. 三个账号都完成签到：两个显示已领取，一个显示今天没有新奖励或已领过。
2. 套餐状态接口返回 `SUBSCRIBED`，签到前检查通过。
3. 奖励账本中每条已出现条目显示 `done=true`，不存在伪造的未领奖励。
4. 自动续费为开启时必须显示账户级警告，不能由签到自动修改。
5. 只读模拟接口可以重复读取，不产生订单或续费变化。
