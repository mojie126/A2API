# 向上游 PR 规范

适用两个方向：本仓库（A2API，fork `mojie126/A2API`，上游 `aimod-cc/Agent2API`）与插件仓库（Agent2Providers，fork `mojie126/A2P`，上游 `ProvidersPlugin/Agent2Providers`）。官方基线、本地改动全史与「可 PR 上游清单」的权威记录见 `docs/baseline-and-local-changes_2026-11-10.md`（插件仓库为其对应文档），整理前先读它。

## 1. 前置核对（动手前）

- 读权威文档的「可 PR 上游清单」，确认条目未被官方覆盖、未被其它贡献者的 PR 承接；已被覆盖的条目在清单里标注后跳过
- PR 内容必须按官方最新基线重整：A2API 对齐官方 beta 最新提交，插件仓库对齐其 beta 最新提交；不得携带 fork 历史提交、不得直接把 develop 分支整枝推上去
- 官方自身修复与本 fork 修复重复时，以官方实现为准，在清单里标注「已覆盖」后不再重复提交
- 整理前在本地确认构建与测试通过：A2API 跑 `cargo test -p agent2api-server --lib` 与前端构建；插件仓库跑 `cargo test --workspace`

## 2. PR 分支

- 命名 `pr/<日期或主题>`，例如 `pr/2026-11-10-raccoon-headers`；从 develop 创建：`git switch -c pr/2026-11-10 develop`
- 把要提交的改动以 cherry-pick 或补丁方式整理进 PR 分支，逐个提交对应可独立验证的改动；提交信息用简体中文
- fork 专属内容一律剥离：工作流触发口径改动（仅手动触发）、发布流程调整（sha256、草稿清理、后缀规则）、本机构建脚本（`scripts/build-desktop.ps1`）、基线记录文档、协议库钉定的本地调整
- 推 `origin/pr/<日期或主题>` 后向官方仓库开 PR，base 选官方 `beta` 分支
- PR 合并或关闭后清理分支：本地与 origin 的 `pr/*` 一并删除（`git branch -D`、`git push origin --delete`）

## 3. PR 正文与落款

- 正文用简体中文，条目式说明改动与意图；关联 Issue 需携带编号（如 Issue #542）
- AI 代理发起或代笔的 PR 与每一条回复，末尾单独一行：🤖 本条回复由 AI Agent 生成；英文场合加 `Generated by an AI agent.`
- 提交作者保持本人账号；涉及用户隐私的实测数据（账号、令牌、主机名）不得进入 PR 内容

- 2026-11-10 已关闭三个旧 PR：A2API #531（客户端归属与图片兼容）、#540（models.dev）、插件仓库 #42（OfficeAce 修复），关闭原因是官方 `3.5.0-beta.1` 基线落地，重整后以新 PR 提交，不复用旧编号
- TOML 配置编辑注释丢失的修复已被官方 `aba58858` 覆盖，不再提交
- 官方 rust-tests 工作流自带 push 触发，属于官方口径，fork 的「仅手动触发」修剪不作为 PR 内容
